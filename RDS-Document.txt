I. Overview
1. System Context 
The BookStore Online System is a comprehensive e-commerce software system that modernizes and replaces the traditional manual processes for browsing, purchasing, and managing books. The context diagram below illustrates the external entities and system interfaces for release 1.0, including interactions between Customers, Sale Staff, Admins, and Warehouse personnel. The system is expected to evolve over several releases, ultimately integrating with advanced third-party logistics APIs (such as GHN), comprehensive online payment gateways (e-wallets and credit/debit card authorization services), and an AI-driven book recommendation engine.

2. External Entities

#
Entity
Description
1
Customer
The entity representing the end user (including visitors and registered members) interacts directly with the system. Customers provide input data such as account identification, search queries, shopping cart/ordering actions, and community interactions (reviews, comments). In return, they receive output data from the system such as book information, order processing status, notifications, and offers (vouchers).
2
Sale Staff
The entity representing the bookstore's operational employees who handle day-to-day customer service and order management. Staff members interact with the system by updating order statuses, resolving customer complaints and return/refund requests, directly replying to product reviews, and managing user F-point transactions. In return, the system provides them with real-time data such as customer support tickets, detailed order lists, user feedback, and F-point audit histories to ensure smooth operations.
3
Admin
The entity representing the system administrators and business managers who oversee the entire bookstore platform. Admins interact with the system by managing the product catalog (adding/editing books and categories), configuring system settings, managing user accounts and authorizations, and setting up marketing campaigns (vouchers, banners). In return, the system provides them with comprehensive analytical reports, sales dashboards, and system logs for strategic decision-making.
4
Warehouse
The entity representing the inventory and fulfillment personnel responsible for physical goods. Warehouse interacts with the system by updating book stock levels, confirming goods receipts, and updating order statuses to "Packed" or "Handed over to carrier". In return, the system provides them with approved order details, packing slips, shipping labels, and low-inventory alerts to ensure timely fulfillment and restocking.
5
GHN
The external entity representing the third-party logistics and delivery service provider. The system interacts with GHN by providing order-specific data such as customer delivery addresses (district and ward codes) and package details. In return, GHN supplies the system with real-time shipping calculations, including accurate delivery fees, estimated lead times, and updated administrative boundary data to dynamically render the frontend checkout UI.
6
VNPay
The external entity representing the third-party payment gateway used to process secure online transactions. The system interacts with VNPay by sending outgoing data such as order information, payment amounts, and unique transaction IDs. In return, VNPay provides the system with incoming response data, including payment processing statuses, secure transaction codes (vnp_ResponseCode), and verification results to finalize or rollback the checkout process.

4.5 User Story
EPIC 1: Authentication
User Story 1: User Login
Description: As a Registered User, I want to log in to the system so that I can access the features and data authorized for my specific role.
Normal Flow (Main Success Scenario):
User navigates to the Login Page.
The System displays the login form (Email/Username and Password fields).
User enters a valid Email and Password.
User clicks the "Login" button.
The System authenticates the credentials against the database and identifies the User Role.
The System creates a session and redirects the user based on their role:
Buyer: Redirected to the Homepage.
Admin: Redirected to the Admin Dashboard.
Warehouse Keeper: Redirected to the Inventory Management page.
Alternative Flows:
AF 1: Remember Me: User selects the "Remember Me" checkbox before logging in. After successful authentication, the system saves a secure cookie to keep the user logged in for future visits.
Exceptions:
EX 1: Invalid Credentials: User enters an incorrect email or password. The system remains on the Login page and displays: "Incorrect login information."
EX 2: Missing Required Fields: User leaves Email or Password blank. The system displays: "Please enter this information" directly under the empty field.
EX 3: Blocked Account: User enters correct credentials, but the account status is set to "Locked/Inactive". The system prevents login and displays: "Your account has been locked. Please contact support."
EX 4: SQL Injection/Malicious Input: User enters invalid characters in fields. The system sanitizes input and rejects the request.

User Story 2: User Logout
Description: As a Registered User, I want to log out of the website so that I can protect my personal data and maintain account security, especially when using a shared or public device.
Normal Flow (Main Success Scenario):
A logged-in User clicks the "Logout" button (found in the Header or User Menu).
The System terminates the current server session.
The System clears local authentication data (cookies/tokens).
The System redirects the user to the Homepage (or Login Page).
The Header/Menu is updated to show "Login" and "Register" buttons instead of user-specific info.
Alternative Flows:
AF 1: Logout from Profile: User logs out specifically from the account settings page. The flow remains the same as the Normal Flow.
Exceptions:
EX 1: Back-button Browser Cache: User clicks the browser's "Back" button after logging out. The system checks for an active session; since none exists, it redirects the user back to the Login Page or displays an "Access Denied" message for restricted pages.
EX 2: Failed Session Termination: If the network fails during the logout request, the system prompts the user: "Unable to logout at this time. Please try again."

User Story 3: Register a New Account
Description: As an Unregistered User, I want to create a new account on the website so that I can manage my profile, track orders, and access member-exclusive features like vouchers and cart saving.
Normal Flow (Main Success Scenario):
User navigates to the Registration Page.
User fills in all required fields: Full Name, Username, Email, Phone Number, Password, and Confirm Password.
User clicks the "Register" button.
The System validates the data formats and checks for existing accounts.
The System creates a new user record with the default 'Customer' role.
The System generates an OTP (One-Time Password) and sends it to the user's email.
The System redirects the user to the OTP Verification Page with a success notification.
Exceptions:
EX 1: Duplicate Account Info: User enters a Username or Email that is already taken. The system remains on the page, retains non-sensitive data, and displays: "Username/Email already exists."
EX 2: Invalid Field Formats:
Email: User enters a string without "@" or ".com". Error: "Invalid email format."
Phone: User enters letters or special characters. Error: "Phone number must contain only digits."
Length: Phone number is too short or too long. Error: "Invalid phone number length."
EX 3: Password Mismatch: "Confirm Password" does not match "Password". The system displays: "Passwords do not match."
EX 4: Weak Password: User enters a password that is too simple (e.g., less than 6 characters). The system displays: "Password must be at least 6 characters long."
EX 5: Empty Mandatory Fields: User leaves required fields blank. The system displays: "This field is required" next to each empty field.
EX 6: Terms and Conditions Not Accepted: (Optional) If there is a checkbox for terms, the system prevents registration if it is unchecked.

EPIC 2: User Management

User Story 1: Edit User Profile (with OTP Verification)
Description: As a Registered User, I want to view and safely update my personal profile information (Full Name, Email, Phone Number) so that my contact details are up-to-date, with sensitive changes protected by OTP verification.
Normal Flow (Main Success Scenarios):
Scenario A: Update Basic Info (Full Name)
The User navigates to the "My Profile" (Hồ sơ cá nhân) page.
The System retrieves and displays the current user data (Username is read-only).
The User modifies the "Full Name" (Họ và tên) directly in the input field.
The User clicks the "Save Changes" (Lưu thay đổi) button.
The System validates the name, updates the database, and displays a success notification.
Scenario B: Update Email (Requires OTP)
The User clicks the "Change" (Thay đổi) button next to the Email field.
The System opens the "Change Email" (Thay đổi Email) modal.
The User enters a new email address and clicks "Send OTP" (Gửi mã OTP).
The System generates a 6-digit OTP and sends it to the newly entered email.
The User enters the 6-digit OTP into the verification field and clicks "Confirm" (Xác nhận).
The System verifies the OTP, updates the email in the database, closes the modal, and refreshes the UI with the new email.
Scenario C: Update Phone Number (Requires OTP via Current Email)
The User clicks the "Change" (Thay đổi) button next to the Phone Number field.
The System opens the "Change Phone Number" (Thay đổi Số điện thoại) modal, displaying the user's current verified email.
The User clicks "Send OTP" (Gửi mã OTP).
The System sends a 6-digit OTP to the user's current email for security authorization.
The User retrieves the OTP, enters it into the modal, and inputs their New Phone Number.
The User clicks "Confirm" (Xác nhận).
The System verifies the OTP and the new phone format, updates the database, closes the modal, and refreshes the UI.
Alternative Flows:
AF 1: Cancel Update: At any point inside the Email or Phone modals, the User clicks the "Back" (Trở về) button or the modal backdrop. The modal closes, and no changes are made to the database.
AF 2: Resend OTP: If the User does not receive the OTP, they can wait for a cooldown timer (if implemented) and click "Resend OTP". The system invalidates the old OTP and sends a new one.
Exceptions:
EX 1: Empty Full Name: The User clears the "Full Name" field and clicks "Save Changes". The system blocks the action and displays an error: "Full Name cannot be blank."
EX 2: Invalid OTP: The User enters an incorrect 6-digit OTP and clicks "Confirm". The system prevents the update and displays an error directly inside the modal: "Invalid or expired OTP. Please try again."
EX 3: Duplicate Email: In the Change Email modal, the User requests an OTP for an email that is already registered to another account. The system halts the action immediately and displays: "This email is already in use by another account."
EX 4: Invalid Email Format: The User types an invalid email (e.g., missing '@') in the modal. The system disables the "Send OTP" button or throws a validation error: "Please enter a valid email address."
EX 5: Invalid Phone Format: In the Change Phone modal, the User enters a valid OTP but an invalid new phone number (e.g., contains letters or wrong length). The system rejects the confirmation and displays: "Phone number must be 10 digits and start with 0."
EX 6: OTP Timeout/Expiration: The User waits too long (e.g., over 5 minutes) to enter the OTP. Upon clicking "Confirm", the system rejects the input and prompts: "OTP has expired. Please request a new one."


User Story 2: Change Account Password
Description: As a Registered User, I want to change my current password from within my account settings so that I can maintain the security of my account and protect my personal data.
Normal Flow (Main Success Scenario):

The System verifies the user is logged in and checks if the requested quantity for all items is available in the current stock.
The System loads the Checkout page, displaying the user's saved Delivery Addresses, Order Summary, Voucher options, and Payment Methods.
The User selects a preferred Delivery Address from the list.
The System automatically calls a third-party API (GHN) based on the selected address's District and Ward to dynamically calculate and display the Shipping Fee and Expected Delivery Date.
The User selects the "COD" (Cash on Delivery) payment method and agrees to the Terms &amp; Conditions.
The User clicks the "Xác nhận thanh toán" (Confirm Payment) button.
The System creates the order in the database, permanently deducts the book stock, removes the purchased items from the user's cart, and redirects the user to the Home page with a success message.
Alternative Flows:
AF 1: Add or Edit Shipping Address: The User clicks "Thêm địa chỉ mới" (Add new) or "Sửa" (Edit) next to an address. The System opens a modal prompting for Name, Phone, and Region. The System performs frontend validation (e.g., no numbers in the name, exactly 10 digits for the phone) before saving the data and refreshing the address list.
AF 2: Apply Voucher: The User clicks "Chọn mã khuyến mãi" to open their Voucher Wallet. The User selects an eligible voucher. The System dynamically calculates the discount (capping at the maximum allowed discount if it's a percentage) and updates the Grand Total in real-time on the interface.
AF 3: Pay via VNPAY: The User selects the "VNPAY" payment method and clicks Confirm. The System temporarily reserves the stock, securely packages the session data (Order ID, Amount), and redirects the user to the external VNPAY secure payment gateway.
Exceptions:
EX 1: Out of Stock Prevention: During Step 2, if the System detects that another customer has just bought the last copy of a book, it immediately aborts the checkout process, redirects the user back to the Cart, and displays an error: "Sản phẩm [Tên sách] chỉ còn [X] sản phẩm!".
EX 2: Backend Voucher Security (Anti-Tampering): Upon submitting the order, the Backend recalculates the applied voucher to ensure it belongs to the user and meets the Minimum Order Value. If the User bypassed the frontend to inject an invalid voucher ID, the System silently nullifies the voucher and charges the original full price to prevent revenue loss.
EX 3: Missing Shipping Address: If the User forcibly submits the form without selecting a shipping address, the Backend catches the missing parameter, blocks the database transaction, and redirects the user back to the checkout page with the error: "Vui lòng chọn địa chỉ giao hàng!".

5.3 Non-UI Functions

#
Feature
System Function
Description
1
Voucher Management
Auto-update Voucher Status (Cron Job)
The system sets up a background process (batch job/cron job) that runs periodically every day (e.g., at 00:00). This process scans all discount code data and compares the endDate with the current date. If a voucher is past its expiration date, the system automatically changes its status to "Expired" without requiring manual staff intervention.
2
Checkout
Calculate Shipping Fee (3rd Party API)
The system automatically calls the Giao Hang Nhanh (GHN) API, passing parameters such as to_district_id, to_ward_code, weight, and package dimensions to retrieve the real-time shipping fee.
3
Checkout
VNPay Payment URL Generator (API/Service)
When a user selects VNPAY as the payment method, the backend (VNPayService) silently generates a secure encrypted string (hash) containing the order code (orderId), amount (amount), and transaction details, then communicates with the VNPAY server to generate a secure payment URL.
4
Checkout
VNPay IPN Listener (Webhook/API)
The system provides a background API (Webhook) to listen for the Instant Payment Notification (IPN) returned from the VNPAY server. As soon as the customer successfully completes the transaction, VNPAY silently calls this API so the system can automatically update the order status to "Paid".
5
Order Management
Auto-cancel Unpaid Orders (Cron Job)
The system runs a periodic background scan (e.g., every 30 minutes). If it detects VNPAY orders that have remained in the "Pending Payment" status beyond the allowed timeframe (e.g., 24 hours), the system will automatically change their status to "Canceled" and automatically restock the quantities for the associated products.
6
Voucher Management
Auto-increment Usage Count (Service)
As soon as an order using a discount code is successfully placed, the system triggers a background function (e.g., markVoucherAsUsed) to increment the usage count of that specific voucher by 1. If the usage count reaches its maximum limit, the system automatically deactivates the code.
7
Inventory Management
Auto-update Stock Quantity (Service)
As soon as a Goods Received Note (GRN) is successfully saved or approved, the system triggers a background function to increment the stock_quantity of the corresponding products in the database to ensure data consistency.
8
Complaint&amp;Return Management
External API &amp; Webhook
A backend service that handles secure payment processing with the VNPAY gateway. It generates secure payment URLs and listens for the asynchronous callback (IPN/Return URL) from VNPAY. Upon a successful transaction code (vnp_ResponseCode == "00"), this service automatically triggers database updates: creating the order, deducting book stock, marking the applied voucher as used, and adding F-Points to the user's account.
9
Logistics API
External API
A service that communicates with the external GHN API to calculate real-time shipping fees and estimated delivery times. It takes the customer's selected destination (Province, District, Ward) and the cart's total weight as inputs, and returns the exact shipping cost to be dynamically added to the checkout total.
10
F-point Management
Internal Logic Service
A background computational logic that evaluates a customer's loyalty status. It dynamically calculates the total F-Points earned (rule: 1 book = 10 points for VNPAY orders) within the current month. Based on the aggregated points, it automatically classifies the user into the appropriate Membership Tier (Bronze, Silver, Gold, Diamond) without requiring manual cron jobs.
11
Event-Driven Notification Trigger
Internal Service
An automated internal service that listens for specific state changes within the database. For instance, when a Sale Staff submits a reply to a customer's product review or updates the status of a support ticket to "Resolved", this trigger automatically inserts a new alert record into the Notifications table, pushing a real-time update to the customer's dashboard.

1. Software Architecture
1.1 Overall Architectural Diagram

1.2 Component Descriptions
No
Component
Description
01
Presentation Logic Layer
The Controller layer (represented by Servlets such as HomeServlet, RegisterServlet, etc.) is responsible for receiving requests from the browser, validating input data, calling the underlying processing layers, and directing the results to the appropriate display page.
02
User Interface
The View class (represented by JSP files in the view directory) is responsible for receiving processed data from the Controller and rendering it into a complete web interface to send back to the Web Browser.
03
Service Layer
This layer contains the system's complex business logic and rules. It handles calculations, condition checks, or calls to external services (such as sending OTP emails) before interacting with the database.
04
Data Access Layer
The data retrieval layer (represented by DAO files such as BookDAO, UserDAO...) contains SQL statements and uses JDBC to interact directly with the database (add, edit, delete, retrieve data).
05
Model Classes
Entity classes (represented by classes like Book, User, etc.) are Java objects (POJOs) that mimic the structure of tables in a database, acting as "containers" for transferring data between layers.
06
Common Classes
Shared utility and configuration layers (represented by DBContext, EmailUtility, etc.) contain support code that is used repeatedly in many places in the system, making it easy to maintain and manage core configurations.
07
Database
Database management system (SQL Server). A physical storage location for all system information (books, users, orders, etc.) in a secure and organized manner.
